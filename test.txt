scripts/run_extractor.py 신규:

플래그	동작
--url URL	분석할 문서 URL (필수)
--mode mock	크롤 + 프롬프트 빌드 + 고정 mock 응답 (기본)
--mode production --api-key AIza...	실제 Gemini 호출
--dump-prompt	구성된 LLM 프롬프트 전체 출력 후 종료
--save-mock	추출 결과를 scripts/seed/generated/mock_<slug>.json으로 저장

사용 예시:
```
# Django CSRF 문서로 실제 프롬프트 확인

# production 모드로 추출 → mock 데이터셋 갱신
python backend/scripts/run_extractor.py --url "https://docs.djangoproject.com/en/6.0/ref/csrf/" --mode production --api-key $env:GEMINI_API_KEY --save-mock
```

생성 파일 구조:

파일	내용
--out-file	전체 터미널 출력
--request-file	LLM에 전송되는 프롬프트 (청크별 구분)
--response-file	파싱된 컨셉 JSON
--response-file + .raw.txt	Gemini 원문 응답 (production 모드만)
프롬프트 구조 요약: Gemini는 단일 user turn — system/user 분리 없음. _build_prompt가 반환하는 하나의 문자열 안에 역할지시 + 스키마 + 문서청크가 모두 포함됩니다.
