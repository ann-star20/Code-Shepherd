## 버전 A — AI 도입·자동화 강조 (일반 AX/DX 직무)

"저는 AI 멀티 에이전트 플랫폼 프로젝트에서 코드 리뷰 자동화 에이전트를 단독으로 설계하고 구현했습니다.

당시 팀에서 겪던 문제는, 시니어 개발자가 신입 PR 리뷰에 하루 1~2시간을 쓰면서도 SQL 인젝션이나 N+1 쿼리 같은 반복 실수가 계속된다는 거였어요.

직접 한 일을 정리하면, 첫째로 LangGraph로 5단계 AI 파이프라인을 설계했고, 심각한 이슈가 탐지되면 실행 경로가 자동으로 에스컬레이션으로 바뀌는 구조를 만들었습니다. 둘째로 Python, JavaScript, C# 등 7개 언어 분석 도구를 통합하고, 과거 유사 이슈를 AI 판단에 활용하는 RAG 파이프라인을 구현했습니다. 셋째로 심각도에 따라 AI 모델을 다르게 쓰는 라우팅 구조를 설계했습니다. 중요한 이슈엔 고성능 모델, 경미한 이슈엔 저비용 모델, 아주 사소한 건 AI 없이 처리해 비용을 처음부터 통제했어요.

여기에 더해 LangSmith로 AI 판단 전 과정을 추적할 수 있는 Observability 체계도 구축했고, 팀 6명이 실제 API 없이 개발할 수 있도록 Mock 전환 구조도 설계했습니다.

AI 도입은 자동화보다, AI 판단이 실제 업무 흐름을 제어하고 비용과 품질이 처음부터 설계될 때 효과가 있다는 것을 직접 경험했습니다. 이 역량을 AX/DX 현장에 바로 기여할 수 있습니다."

## 버전 B — 데이터·분석 강조

"저는 개발팀 신입 온보딩 자동화 플랫폼에서 코드 품질 분석 에이전트를 단독 구현했습니다.

핵심 문제는 반복되는 코드 실수가 데이터로 쌓이지 않아 조직 차원의 개선이 불가능하다는 거였어요.

제가 구현한 파이프라인은 PR이 올라오면 자동으로 분석이 실행되고, 탐지된 이슈가 PostgreSQL에 건별로 쌓이며, BigQuery로 집계되는 구조입니다. 여기에 Airflow DAG로 일일 ETL과 주간 리포트를 자동화했고, LangSmith 트레이싱으로 AI 판단 이력과 품질을 추적할 수 있는 Observability 체계까지 구축했습니다.

이슈 심각도, 발생 파일, 개발자별 패턴이 정량화되어 '이 개발자는 SQL 처리에서 반복 실수한다'는 데이터 기반 인사이트가 가능해졌습니다.

또한 AI 모델 비용을 줄이기 위해 심각도에 따라 다른 모델을 쓰는 라우팅 구조를 설계해, 품질은 유지하면서 비용을 통제하는 경험도 했습니다.

데이터로 업무를 개선하고, AI 도입 비용과 품질을 동시에 설계하는 역량을 이 프로젝트에서 쌓았습니다."

## 버전 C — "어려웠던 점" 질문 대비 (시행착오 스토리)

"개발 중 가장 어려웠던 부분은 비동기 타임아웃 처리였습니다.

에이전트가 30초를 초과하면 DB에 실패로 기록되어야 하는데, 자꾸 성공으로 기록되는 버그가 있었어요. 코드를 보면 분명 TimeoutError를 잡고 있었는데 DB 로그와 실제 동작이 달랐습니다.

원인을 분석해보니, Python의 `async with` context manager는 블록 안에서 예외가 발생하면 `__aexit__`을 호출하는데, 블록 안에서 TimeoutError를 잡아버리면 context manager 입장에서는 '예외가 없었다'고 판단해 성공으로 기록하는 거였습니다. try/except를 `async with` 블록 바깥으로 이동하니 해결됐어요.

해결 후에는 이 패턴을 팀 전체 규칙 문서에 바로 문서화해서 다른 팀원들이 같은 실수를 반복하지 않도록 했습니다.

라이브러리 내부 동작을 이해해야 풀리는 문제였고, 발견한 인사이트를 팀 자산으로 만드는 습관을 이 경험에서 들였습니다."
