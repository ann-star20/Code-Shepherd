## Q1. MVP랑 프로토타입은 어떻게 실행해?

**A.** 3단계로 실행합니다.

1. **DB 켜기** — `docker compose up -d postgres` (데이터 저장소 시작)
2. **서버 켜기** — `python -m uvicorn dev2.main:app --port 8005` (API 서버 시작)
3. **테스트** — `curl -X POST http://localhost:8005/scan/mock-bandit` (스캔 실행)

결과로 `{"status":"success", "issue_count":10, "summary":{"critical":2,"major":3,"minor":5}}` 같은 JSON이 옵니다.

## Q2. 분석할 코드는 어디서 받아와?

**A.** Dev2는 직접 GitHub에서 코드를 가져오지 않습니다.

```
GitHub PR 생성
    ↓
Dev1이 PR 내용을 읽어서 Dev2에게 전달
    ↓
Dev2는 받은 내용을 분석만 함
```

Dev2 입장에서는 "누군가 분석할 코드를 보내줬다"고만 알면 됩니다. 누가 어떻게 보내는지는 Dev1 담당입니다.

## Q3. diff가 뭐야? 데이터 형태가 어떻게 생겼어?

**A.** diff는 "파일에서 무엇이 바뀌었는지"를 보여주는 텍스트입니다.

```diff
--- a/auth.py   ← 바뀌기 전 파일
+++ b/auth.py   ← 바뀐 후 파일
@@ -10,6 +10,8 @@
     if user == "admin":
+        query = f"SELECT * FROM users WHERE id = {user_id}"   ← 새로 추가된 줄 (+)
+        db.execute(query)
         return True
```

- `+` 로 시작하는 줄 = 이번 PR에서 새로 추가된 코드
- `-` 로 시작하는 줄 = 삭제된 코드

Dev2는 이 중 `+` 줄만 골라서 "새로 생긴 취약점"을 탐지합니다.

## Q4. Dev2는 GitHub랑 전혀 안 연결돼?

**A.** 맞습니다. Dev2 코드 어디에도 GitHub API 관련 코드가 없습니다.

역할 분담:
- **Dev1**: GitHub Webhook 수신, PR diff 추출, Dev2 호출
- **Dev2**: 받은 diff 분석, 결과 DB 저장
- **Dev4**: Dev2 결과를 GitHub에 코멘트로 달기

Dev2는 가운데서 "분석"만 담당합니다.

## Q6. Docker에서 "dockerDesktopLinuxEngine 없다"고 에러 나면?

**A.** Docker context가 잘못 설정된 겁니다. 아래 명령어로 해결합니다:

```bash
docker context use default
```

Windows에서 Docker Desktop이 아닌 일반 Docker를 쓸 때 발생합니다. 항상 작업 시작 전에 한 번 실행해두면 됩니다.
