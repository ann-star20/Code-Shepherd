## 📌 STAR 7항목 (포트폴리오 본문)

### 01 프로젝트 소개

- **프로젝트 이름:** Task-Link — 사내 지식·온보딩 멀티 에이전트 플랫폼 (PR 자동 코드리뷰 모듈)
- **한 줄 소개:** GitHub PR이 올라오면 AI가 자동으로 정적분석·보안스캔을 수행하고, 과거 유사 사례(RAG)와 LLM 판단을 결합해 심각도를 매기고 리뷰 코멘트까지 자동 생성하는 **AI 네이티브 코드리뷰 에이전트**
- **참여 인원 / 기간:** 6인 팀(FE 1 + 백엔드/에이전트 5), 약 6주 (Week1 설계 ~ Week6 데모)
- **내 역할:** **Dev2(M2) — 정적분석 + 보안스캔 에이전트 단독 설계·구현** (FastAPI 서비스, LangGraph 파이프라인, 도구 라우터, RAG, 통계 API, ETL 전 영역)
- **사용 기술:** Python 3.11, FastAPI, LangGraph, LangSmith, Claude(sonnet-4-6/haiku-4-5), PostgreSQL + pgVector(RAG), BigQuery(OLAP), Airflow, Bandit·Pylint·ESLint·Semgrep·Radon 등 분석 도구, Docker

### 02 프로젝트 개요 | 배경과 목적

- **왜 시작되었나:** 신입 개발자 온보딩 과정에서 PR 코드리뷰가 전적으로 시니어의 수작업에 의존 → 리뷰 품질이 사람·시간에 따라 들쭉날쭉하고, 시니어 리소스가 병목이 됨.
- **해결하려던 문제:** ① 보안 취약점(SQL 인젝션·하드코딩 시크릿 등)이 사람 눈에 의존해 누락 ② 리뷰 기준이 표준화되지 않아 같은 실수가 반복 ③ 신입의 "반복 실수 패턴"이 데이터로 쌓이지 않아 성장 추적 불가.
- **AX/DX 관점:** "리뷰어의 경험·기억"에 갇힌 암묵지를 **자동화된 파이프라인 + 데이터(이슈 적재)** 로 전환. 보안 점검을 자동화하고(AX), 리뷰 결과를 분석 가능한 데이터로 축적해 개인·팀 성장 지표로 데이터화(DX)하는 것이 목표.

### 03 진행한 일 | 배경-문제-해결

- **문제 상황:** PR마다 언어·위험요소가 다른데, 모든 도구를 무조건 다 돌리면 느리고 비싸며, 사람이 일일이 판단하면 일관성이 없음.
- **핵심 원인:** (1) 분석 도구 실행이 PR 맥락과 무관하게 고정 (2) CLI 도구의 기계적 심각도가 실제 위험도를 반영 못함 (3) 결과가 1회성으로 사라져 학습·통계로 이어지지 않음.
- **해결 방향:** "단순 도구 실행 스크립트"가 아니라 **LLM 판단으로 실행 경로가 바뀌는 Agentic Workflow**로 설계. 맥락 기반 도구 선택 → 도구 실행 → RAG 유사사례 → LLM 심각도 재판단 → 후속 액션 추천 → 이중 저장.
- **내가 선택한 접근:** LangGraph StateGraph 7노드 + 조건부 엣지(Critical 시 즉시 에스컬레이션 분기), 비용 통제를 위한 **심각도별 모델 라우팅**, 모든 결과를 OLTP(PostgreSQL)+OLAP(BigQuery)에 적재해 통계 API로 환원.

### 04 과정 | 직접 한 일 + 인사이트

- **① 다국어 분석 라우터 설계** — 파일 확장자 → (언어·정적·보안·의존성 도구) 디스패치 테이블로 구성해 **6개 언어 / 10종 도구**를 한 줄 추가로 확장 가능하게 만듦. if/elif 분기 대신 매핑 테이블을 택한 건 "신규 언어 추가 시 코드 수정 최소화"라는 운영 확장성 기준 때문.
- **② Agentic Workflow 구현** — `tool_router_agent`가 PR diff의 보안 키워드·의존성 변경·과거 PR 이력을 분석해 **필요한 도구만 선택 실행**. 무조건 전체 실행 대비 불필요한 비용·시간 제거.
- **③ RAG + LLM 심각도 재판단** — pgVector 코사인 유사도(top-k=3, threshold 0.7)로 과거 유사 이슈를 주입한 뒤 LLM이 심각도를 재조정. **Critical→sonnet-4-6 / Major→haiku-4-5 / Minor→LLM 생략**의 3단 모델 라우팅으로 정확도와 비용을 동시에 잡음.
- **④ 데이터화 + 자동화 파이프라인** — 분석 결과를 PostgreSQL·BigQuery에 이중 적재, Airflow DAG(매일 ETL + 주간 리포트)로 자동 집계, `/insights` API로 개발자별·팀별·주간 Critical 추이를 제공.
- **⑤ 품질 게이팅 체계 구축** — LangSmith 골든 데이터셋(7케이스)으로 심각도 판단 정확도를 측정하고 **70% 미달 시 머지 차단**. 단위 테스트 **188개**를 Mock 기반으로 작성해 DB·LLM 없이도 CI가 돌도록 함.
- **시행착오:** 테스트/CI 환경엔 asyncpg·langchain이 없어 import만으로 실패 → **lazy import 패턴**으로 실행 시점에만 의존성을 로드하게 바꿔 "환경 변경 없이 Mock↔실제 전환"을 달성.
- **인사이트:** AI 자동화의 핵심은 모델이 아니라 **"실패해도 멈추지 않는 파이프라인 설계"**(0결과·DB실패·파싱오류 fallback)와 **재현 가능성**이라는 걸 체득.

### 05 결과물 | 최종 + 포인트

- **완성물:** PR diff를 입력받아 분석→판단→저장→코멘트→알림까지 처리하는 독립 실행형 FastAPI 에이전트 서비스(M2). 공용 Webhook 게이트웨이에도 어댑터로 연동(등록 테스트 15개 통과).
- **핵심 기능:** ① 맥락 기반 도구 자동 선택 ② RAG 기반 심각도 재판단 ③ Critical 즉시 에스컬레이션 분기 ④ OLTP+OLAP 이중 적재 ⑤ 개발자/팀/추이 통계 API.
- **시스템 흐름:** `tool_router → run_tools → vector_search(RAG) → llm_judge → action_decider → (escalate) → store → 통계/ETL`
- **정량 성과:** 7노드 Agentic 파이프라인 / 6개 언어·10종 도구 통합 / 3단 모델 라우팅 / 단위테스트 **188개** / 품질 게이트 70% / SQL 마이그레이션 4종 / 일·주 단위 ETL DAG 2종.
- **정성 성과:** 코드리뷰 기준의 **표준화·자동화**, DB·LLM 없이 돌아가는 **재현 가능한 파이프라인**, 신규 언어/도구 **확장 용이 구조**, 리뷰 결과를 성장 지표로 환원하는 **데이터 기반 의사결정 근거** 확보.

### 06 성장한 점

- **기술적:** LangGraph 조건부 분기로 "스크립트"와 "Agentic Workflow"의 차이를 직접 구현. RAG·모델 라우팅·OLTP/OLAP 분리를 한 서비스 안에서 설계.
- **문제 해결:** 장애 내성(fallback) 중심으로 사고하게 됨 — 외부 의존성 실패를 전제로 설계해야 자동화가 실제로 굴러간다는 점.
- **협업:** 6인 병렬 개발에서 **Output Contract(JSON)·State 스키마·라우터 분리**로 충돌 없이 통합하는 인터페이스 설계 경험. 게이트웨이 기존 코드는 한 줄만 추가하고 어댑터로 위임해 타 팀원 코드 무수정 원칙 준수.
- **비즈니스 이해:** "보안 점검 자동화"가 끝이 아니라, 결과를 데이터로 쌓아야 온보딩·성장이라는 비즈니스 목표로 연결된다는 걸 이해.

### 07 나의 역량 | 입사 시 기여

- **보여줄 역량:** 반복적 수작업(코드리뷰·보안점검)을 **AI 파이프라인으로 자동화**하고, 그 결과를 **분석 가능한 데이터로 전환**하는 End-to-End 설계력.
- **AX/DX 연결 강점:** ① 업무 자동화(Agentic Workflow) ② 데이터화(OLTP/OLAP·통계 API) ③ 비용 최적화(모델 라우팅) ④ 품질 게이팅으로 신뢰성 확보 — AX/DX의 핵심 요소를 한 프로젝트에서 모두 다룸.
- **입사 후 기여:** 사내 수작업 프로세스를 LLM 에이전트로 자동화하고, 결과를 대시보드/지표로 환원해 의사결정을 데이터 기반으로 바꾸는 PoC~운영화를 주도할 수 있음.
- **한 줄 어필:** *"저는 사람의 경험에 의존하던 코드리뷰를, 실패해도 멈추지 않는 AI 파이프라인과 측정 가능한 데이터 체계로 바꿔본 사람입니다."*

## ✍️ 자기소개서용 (약 700자)

신입 개발자 온보딩에서 코드리뷰가 전적으로 시니어의 수작업에 의존해, 리뷰 품질이 일관되지 않고 보안 취약점이 누락되며 반복 실수가 데이터로 쌓이지 않는 문제가 있었습니다. 저는 이 수작업 리뷰를 AI가 자동 수행하는 정적분석·보안스캔 에이전트(M2)를 단독으로 설계·구현했습니다.

단순히 도구를 실행하는 스크립트가 아니라, LangGraph로 PR 맥락에 따라 실행 경로가 바뀌는 7노드 Agentic Workflow를 구축했습니다. PR 내용을 분석해 6개 언어·10종 도구 중 필요한 것만 선택 실행하고, pgVector RAG로 과거 유사 사례를 주입한 뒤 LLM이 심각도를 재판단하도록 했습니다. 이때 Critical은 고성능 모델, Major는 경량 모델, Minor는 LLM을 생략하는 비용 최적 라우팅을 적용했습니다. 또한 모든 결과를 PostgreSQL과 BigQuery에 이중 적재하고 Airflow ETL과 통계 API로 환원해, 일회성 리뷰를 개인·팀 성장 지표로 데이터화했습니다.

CI 환경에 외부 의존성이 없어 실패하던 문제는 lazy import로 해결해 환경 변경 없이 Mock↔실제 전환을 달성했고, 골든 데이터셋 정확도 70% 미달 시 머지를 차단하는 품질 게이트와 단위테스트 188개로 신뢰성을 확보했습니다.

이 경험으로 반복 수작업을 AI 파이프라인으로 자동화(AX)하고 그 결과를 분석 가능한 데이터로 전환(DX)하는 End-to-End 설계력을 갖췄습니다. 입사 후에도 사내 수작업 프로세스를 LLM 에이전트로 자동화하고 데이터 기반 의사결정으로 전환하는 데 기여하겠습니다.

## 🎤 면접 답변용 60초 버전

"제가 단독으로 맡은 건 PR이 올라오면 AI가 자동으로 코드리뷰를 해주는 정적분석·보안스캔 에이전트였습니다. 기존엔 시니어가 일일이 손으로 리뷰해서 품질도 들쭉날쭉하고 보안 누락도 잦았는데, 이걸 자동화하는 게 목표였습니다.

핵심은 단순 도구 실행이 아니라, LangGraph로 PR 맥락에 따라 실행 경로가 바뀌는 에이전트 워크플로우로 만든 점입니다. PR 내용을 보고 6개 언어·10종 도구 중 필요한 것만 골라 돌리고, RAG로 과거 유사 사례를 찾아 붙인 다음 LLM이 심각도를 다시 판단합니다. 비용을 줄이려고 심각도별로 모델을 다르게 쓰는 라우팅도 적용했고요.
