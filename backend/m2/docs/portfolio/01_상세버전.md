# Task-Link — AI 코드 리뷰 자동화 에이전트 포트폴리오 (상세 버전)

---

## 01 프로젝트 소개

- **프로젝트명**: Task-Link
- **한 줄 소개**: 사내 지식을 AI가 자동 구조화하고, 신입 개발자의 PR 코드 리뷰·학습 경로를 자동화하는 멀티 에이전트 플랫폼
- **기간 / 인원**: 2026년 5월 (6주) / 6명 (FE 1명 + 서비스 5명)
- **내 역할**: Dev2 — 정적 분석 + 보안 스캔 에이전트 설계 및 단독 구현
- **사용 기술**: Python 3.11, LangGraph, FastAPI, Claude Sonnet 4.6 / Haiku 4.5, pgVector, PostgreSQL (Cloud SQL), BigQuery, Bandit, Pylint, ESLint, Semgrep, radon, pip-audit, Airflow, LangSmith, Docker

## 02 배경과 목적

### 왜 시작됐는가

개발 팀 내 신입 온보딩 과정에서 반복적으로 발생하는 비효율 문제를 해결하기 위해 시작됐다.

- 시니어 개발자가 신입 PR 리뷰에 **하루 1~2시간 소비** — SQL 인젝션, N+1 쿼리 같은 동일한 실수에 매번 같은 피드백
- PR 리뷰 대기 시간이 길어 **개발 흐름이 단절**되고, 신입 개발자의 성장이 멘토 역량에 전적으로 의존
- 반복 실수를 **데이터로 추적하는 체계가 없어** 문제 패턴을 조직 차원에서 파악 불가

### AX/DX 관점에서 무엇을 개선하려 했는가

- **AX (AI Transformation)**: 시니어 개발자의 경험과 판단을 LLM으로 자동화 — 코드 리뷰의 AI 내재화
- **DX (Digital Transformation)**: PR 제출 → 자동 분석 → 즉시 피드백의 디지털 파이프라인 구축, 개발자 성장 데이터의 정량화

## 03 문제-원인-해결 방향

### 문제 상황
PR이 제출되면 시니어 개발자가 직접 코드를 읽고 보안 취약점·코드 품질 이슈를 찾아야 했다. SQL 인젝션, 하드코딩된 패스워드 같은 패턴은 반복 발생함에도 매번 사람이 검토했다.

### 핵심 원인
- 정적 분석 도구(Bandit, Pylint 등)가 있어도 **CI 파이프라인에 통합되지 않아** PR마다 수동 실행
- 도구가 탐지한 이슈를 **severity 기준으로 자동 분류하고 개인화된 피드백을 주는 레이어가 없었음**
- 과거 유사 이슈와의 연결이 없어 **반복 실수 패턴을 학습 자료로 연결하지 못함**

### 해결 방향
GitHub PR 수신 시 자동으로 정적 분석 + 보안 스캔을 실행하고, LLM이 severity를 재판단해 Critical 이슈는 즉시 에스컬레이션, 나머지는 맞춤형 피드백으로 전달하는 AI 에이전트 파이프라인 구축

### 내가 선택한 접근 방식
단순 도구 실행 래퍼가 아닌 **RAG + LLM Judge + Conditional Routing** 조합의 Agentic Workflow로 설계 — 과거 유사 이슈를 context로 주입하여 LLM 판단 정확도 향상, 비용은 severity별 모델 라우팅으로 최적화

## 04 나의 액션 + 인사이트

### 직접 한 일

- **LangGraph 5-노드 StateGraph 설계 및 구현**: `run_tools → vector_search → llm_judge → [escalate] → store` 파이프라인을 Agentic Workflow로 설계. Critical 이슈 유무에 따라 실행 경로가 동적으로 분기되는 conditional edge 적용 — 이것이 단순 자동화와 AI Native Workflow를 구분하는 핵심

- **7개 언어 분석 도구 통합 래퍼 구현**: Python(Bandit·Pylint·radon), JavaScript(ESLint·npm-audit), C#(Roslyn), HTML/CSS(HTMLHint·Stylelint) — 각 도구의 출력을 Pydantic 모델로 통일된 이슈 스키마로 정규화. Pydantic 경계 검증을 통해 내부 필드(llm_judged, _source 등)가 Dev4로 누출되지 않도록 설계

- **RAG 기반 유사 이슈 검색 구현**: pgVector에서 현재 이슈 메시지를 임베딩하여 코사인 유사도 0.7 이상 과거 이슈를 LLM context로 주입 — 단순 도구 탐지 대비 판단 정확도 향상. 0결과 시 예외 없이 빈 리스트 반환으로 파이프라인 안정성 확보

- **비용 최적화 LLM 모델 라우팅 설계**: Critical → claude-sonnet-4-6, Major → claude-haiku-4-5, Minor → LLM 생략. 보안에 직결되는 이슈엔 고성능 모델, 리팩토링 수준 이슈엔 저비용 모델 배치. Minor 이슈 LLM 비용 0원 달성

- **Mock/실제 전환 설계 (USE_MOCK_LLM)**: 환경변수 하나로 코드 변경 없이 Mock ↔ 실제 LLM을 전환하는 구조 설계. 팀 6명이 실제 API 없이 Mock 기반 병렬 개발을 진행할 수 있게 했고, Week 5 통합 시 URL 교체만으로 연결 가능한 구조 마련

- **OLTP + OLAP 이중 적재 파이프라인 구현**: PostgreSQL(Cloud SQL)에 운영 조회용 3-테이블 구조 적재, BigQuery에 분석용 집계 데이터 비동기 적재. BigQuery 장애 시 파이프라인 중단 없도록 예외 격리 설계

- **Airflow DAG 구현**: 일일 ETL DAG(scan_issues 집계 갱신)와 주간 리포트 DAG(개발자별 실수 패턴 리포트 자동 생성) 구현 — 데이터 파이프라인 자동 스케줄링 체계 마련

- **LangSmith 트레이싱 연동**: 모든 LLM 호출에 LangChain 트레이서를 config로 주입해 에이전트 실행 전 과정을 LangSmith에서 추적 가능하게 구현. 환경변수 LANGCHAIN_TRACING_V2=true만으로 활성화되도록 코드 내 하드코딩 없이 설계 (AI 관찰성/Observability)

### 기술 선택 이유

- **LangGraph 선택 이유**: 단순 함수 체인으로는 "LLM 판단 결과에 따라 실행 경로가 달라지는" Agentic Workflow 구현이 어렵다. StateGraph의 conditional_edges가 이 요구를 자연스럽게 표현함
- **모델 라우팅 이유**: 모든 이슈에 Sonnet을 쓰면 Minor 이슈 수백 개에 불필요한 비용 발생. severity를 기준으로 모델을 나누는 것이 품질-비용 균형 최적점
- **Pydantic Output Contract 이유**: 팀 간 API 계약을 코드 수준에서 강제해야 통합 시 충돌이 없다. 문서만으로는 팀원이 내부 필드를 실수로 넘길 수 있음

### 시행착오와 해결

- **asyncio.TimeoutError 처리 위치 문제**: `async with AgentHarness` 블록 안에서 타임아웃을 잡으면 `__aexit__`이 성공으로 판단해 DB에 `status='success'`가 기록됨. 처음에는 원인을 찾지 못해 DB 로그와 실제 동작이 불일치하는 버그로 시간을 소비했다. try/except를 with 블록 바깥으로 이동하고, 이 패턴을 CLAUDE.md에 팀 전체 규칙으로 문서화해 재발 방지

- **LLM 오탐 처리**: LLM이 간혹 `"Crtical"`(오타), `"Blocker"`(정의 외 값) 같은 응답을 반환. 허용값 frozenset 검증 + 1회 재시도 + fallback(원래 severity 유지) 3단 방어 로직 구현. JSON 파싱 실패도 동일한 패턴으로 처리

- **Mock 임베딩의 결정적(deterministic) 설계**: 해시 기반 Mock 벡터를 사용해 같은 입력에 항상 같은 벡터가 나오도록 설계 — 테스트가 랜덤 결과에 의존하지 않도록 함

### 얻은 인사이트

> "Agentic Workflow의 가치는 단순 자동화가 아니라, AI 판단 결과에 따라 실행 경로 자체가 달라지는 것에 있다. 또한 AI를 팀에 도입할 때 Observability(LangSmith)와 비용 구조(모델 라우팅)를 처음부터 설계하지 않으면 나중에 통제 불가 상태가 된다는 것을 직접 경험했다."

## 05 결과물

### 완성물
Dev2 단독 구현 Task 1~8 전체 완료. mock-bandit → PostgreSQL 저장 E2E 테스트 통과.

### 핵심 기능
- GitHub PR diff 수신 → 자동 정적 분석 + 보안 스캔 (7개 언어)
- RAG 유사 이슈 검색 → LLM severity 재판단 (Sonnet/Haiku 모델 라우팅)
- Critical 이슈 자동 에스컬레이션 (Dev4 webhook 전송)
- scan_executions → scan_issues → scan_summaries 3-테이블 영구 저장
- FastAPI REST API: `POST /scan`, `GET /insights`, `GET /issues`, `PATCH /dismiss`
- Airflow DAG: 일일 ETL + 주간 리포트 자동화
- LangSmith 트레이싱: 에이전트 전 실행 이력 추적 및 품질 모니터링

### 시스템 구조

```
GitHub PR diff
    ↓
[run_tools] — Bandit/Pylint/ESLint/Semgrep 병렬 실행 (7개 언어)
    ↓
[vector_search] — pgVector RAG 유사 이슈 검색 (코사인 유사도 ≥ 0.7)
    ↓
[llm_judge] — Claude Sonnet(Critical) / Haiku(Major) / 생략(Minor) severity 재판단
    ↓ (conditional edge)
[escalate] → Dev4 webhook (Critical ≥ 1 시 자동 분기)
    ↓
[store] — PostgreSQL(OLTP) + BigQuery(OLAP) 이중 적재
    ↓
[LangSmith] — 전 단계 실행 트레이스 자동 기록
```

### 정량·정성 성과
- 목표 기준: 시니어 PR 리뷰 부담 70% 감소, 문서 탐색 시간 80% 감소 (PRD 정의 기대 효과)
- 7개 언어 분석 도구 통합으로 언어 무관 분석 기반 마련
- Minor 이슈 LLM 비용 0원 (모델 라우팅으로 CLI 판단 신뢰)
- OLTP/OLAP 이중 적재로 운영 조회와 BI 분석 분리 — BigQuery 기반 주간 리포트 자동화
- LangSmith Observability로 AI 판단 품질 모니터링 기반 확보
- Mock/실제 전환 설계로 팀 6명 병렬 개발 실현 (통합 대기 없음)

## 06 성장한 점

### 기술적 성장
- LangGraph StateGraph의 conditional_edges를 활용한 Agentic Workflow 설계 역량 확보
- RAG 파이프라인(Retrieve → Generate) 설계 및 pgVector 쿼리 최적화 경험
- 비동기 처리(asyncio.gather)와 에러 격리 패턴 — 한 노드 실패가 전체를 멈추지 않는 구조 설계
- LangSmith를 활용한 AI Observability 설계 — LLM 호출 이력·비용·성능 추적 체계 구축
- Airflow DAG를 통한 데이터 파이프라인 스케줄링 자동화

### 문제 해결 방식
- "일단 돌아가게" 대신 에러 발생 케이스를 먼저 정의하고 방어 로직을 선 구현. LLM 오탐, 타임아웃, DB 장애, JSON 파싱 실패 시나리오 각각의 fallback을 코드 작성 전 문서화
- asyncio.TimeoutError 처리 위치 버그처럼, 라이브러리 내부 동작(context manager의 __aexit__)을 이해해야 풀리는 문제를 직접 디버깅한 경험

### 협업
- Dev1(오케스트레이터), Dev4(평가 에이전트)와의 API 계약(Output Contract)을 Pydantic 모델로 명문화 — 실제 연결 전 Mock 기반 병렬 개발 가능하게 함
- USE_MOCK_LLM 설계로 팀 전체가 실제 API 키 없이 개발 진행 가능
- 팀 연동 가이드 문서 직접 작성 → Dev1/Dev4가 연결 방법을 코드 없이 파악 가능
- asyncio 타임아웃 처리 패턴을 발견 후 CLAUDE.md(팀 규칙 문서)에 즉시 문서화해 팀 전체 재발 방지

### 비즈니스 이해
- 기술이 아니라 "시니어 개발자의 시간 절약"이라는 비즈니스 목표를 먼저 설정하고, 그 목표에서 Critical 에스컬레이션 우선순위를 역산한 경험
- AI 도입 비용(LLM 호출)을 처음부터 설계 단계에서 통제하는 모델 라우팅 구조를 직접 설계

## 07 나의 역량 → 입사 기여

### 이 프로젝트로 보여줄 수 있는 강점

- **AI 파이프라인 설계 역량**: LLM을 단순 호출하는 수준을 넘어, Agentic Workflow로 AI 판단이 프로세스 흐름을 제어하는 구조를 설계하고 구현
- **AI Observability 설계**: LangSmith 트레이싱을 코드 내 하드코딩 없이 config 주입 방식으로 설계 — AI 시스템 운영에 필수적인 모니터링 기반 구축 경험
- **비용-품질 균형 감각**: 모델 라우팅, LLM 생략 기준, 이중 적재 분리 등 기술 결정마다 비즈니스 비용을 고려
- **데이터 파이프라인 이해**: OLTP(운영 조회)와 OLAP(분석)의 목적 차이를 구분하고 이중 적재 + Airflow 스케줄링 구조 설계
- **협업 설계 역량**: Mock/실제 전환 구조와 Pydantic Contract 명문화로 팀 병렬 개발 실현 — AI 도입 프로젝트에서 팀 간 인터페이스 설계 역량

### AX/DX 직무 연결 포인트

| 직무 역량 | 프로젝트 근거 |
