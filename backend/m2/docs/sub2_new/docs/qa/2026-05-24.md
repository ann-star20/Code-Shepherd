## Q2. HTTP 상태코드 200 vs 202 차이가 뭐야?

**A.**

- **200 OK** = "요청 완료됐어요. 결과 여기 있어요."
- **202 Accepted** = "접수는 됐어요. 근데 아직 처리 중이에요."

예를 들어, 카페에서 음료를 주문하면:
- 200 = 주문하자마자 음료를 바로 줌 (즉시 완료)
- 202 = "주문 접수됐습니다!" 영수증만 먼저 줌 (음료는 나중에)

우리 프로젝트에서 POST /scan이 202인 이유: LLM 분석은 수 초~수십 초 걸리기 때문에 "접수됐다"는 응답만 먼저 보내고, 실제 분석은 백그라운드에서 실행해요.

## Q3. BackgroundTasks가 뭐야?

**A.** FastAPI에 내장된 기능으로, **응답을 먼저 보내고 나서** 뒤에서 추가 작업을 실행해줘요.

```
클라이언트 요청
    → FastAPI가 202 응답 먼저 전송 (사용자는 즉시 결과 받음)
    → 응답 전송 완료 후, 백그라운드에서 LLM 분석 실행
```

치킨집 비유: 주문받으면 "30분 후 배달됩니다" 문자 먼저 보내고, 실제로 치킨은 그 뒤에 굽는 것과 같아요.

코드에서는 이렇게 씁니다:
```python
background_tasks.add_task(run_dev2, initial_state)  # 나중에 실행할 함수 등록
return {"status": "accepted"}  # 응답은 바로 반환
```

## Q4. APIRouter가 뭐고 왜 파일을 분리해?

**A.** FastAPI에서 URL 경로(엔드포인트)를 파일별로 나눠 관리하는 도구예요.

**왜 분리하나?**
- 6명이 동시에 개발할 때, 한 파일에 몰아넣으면 서로 충돌남
- `scan.py` / `insights.py` / `issues.py`로 나누면 각자 독립적으로 작업 가능

```python
# insights.py
router = APIRouter(prefix="/insights")  # 이 라우터의 모든 경로 앞에 /insights 자동 붙음

# main.py에서 조립
app.include_router(insights_router)  # /insights/developer, /insights/team 등 등록됨
```

레고 블록처럼: 각 파일은 블록 하나, main.py가 조립만 담당해요.

## Q5. PATCH vs PUT vs DELETE — 어떻게 구분해?

**A.**

| 동사 | 의미 | 언제 쓰나 |
|------|------|-----------|
| GET | 읽기 | 데이터 조회 |
| POST | 새로 만들기 | 작업 시작, 데이터 생성 |
| PUT | 전체 교체 | 레코드 전체를 새 값으로 덮어씀 |
| PATCH | 일부 수정 | 특정 필드 하나만 바꿀 때 |
| DELETE | 삭제 | 레코드 삭제 |

오탐 표시(`/issues/{id}/dismiss`)에 PATCH를 쓴 이유:
- `is_false_positive` 필드 **하나만** 바꾸면 되니까
- 이슈 기록 자체는 유지해야 하니까 DELETE는 안 됨

## Q6. Lazy Import(함수 내부 import)가 뭐야? 왜 써?

**A.** 보통은 파일 맨 위에 `import`를 쓰는데, 함수 안에서 import하는 걸 "lazy import(지연 임포트)"라고 해요.

**왜 쓰나?**  
- `asyncpg`(데이터베이스 드라이버)가 설치 안 된 테스트 환경에서도 파일을 불러올 수 있게 하기 위해서
- 파일 상단에 있으면 → 파일 자체를 불러올 때 바로 에러
- 함수 안에 있으면 → 그 함수가 실제로 호출될 때만 에러 (테스트에서는 함수 자체를 Mock으로 교체)

```python
# ❌ 이렇게 하면 asyncpg 없는 환경에서 import 자체가 실패
from dev2.db import AsyncSessionLocal  # 파일 상단

# ✅ 이렇게 하면 함수 호출 시점까지 에러 안 남
async def get_developer_insights(developer_id: str):
    from dev2.db import AsyncSessionLocal  # 함수 내부
    async with AsyncSessionLocal() as s:
        ...
```

## Q7. Mock 테스트가 뭐야? 왜 실제 DB 없이 테스트해?

**A.** Mock = 가짜(모형). 실제 데이터베이스 대신 "이런 결과를 돌려줘"라고 약속한 가짜 객체를 쓰는 것.

**왜 쓰나?**
- 실제 PostgreSQL이 없어도 테스트 통과 가능
- 테스트 속도가 훨씬 빠름
- CI 서버(자동 빌드 환경)에 DB 설치 안 해도 됨

비유: 배우가 실제 총 대신 모형 총으로 연기 연습하는 것. 실제 총은 위험하니까.

`patch("dev2.db.AsyncSessionLocal", return_value=_mock_db_ctx())` 이 코드가 핵심인데, "실제 DB 연결 함수를 가짜로 교체하라"는 뜻이에요.

## Q8. `patch("dev2.db.X")` vs `patch("dev2.api.insights.X")` — 어느 쪽을 패치해야 해?

**A.** 함수를 어디서 import했냐에 따라 달라요.

| import 방식 | patch 대상 |
|-------------|-----------|
| 파일 상단 `from dev2.db import X` → `insights.py`에 복사됨 | `dev2.api.insights.X` |
| 함수 내부 `from dev2.db import X` → 호출 시마다 원본에서 가져옴 | `dev2.db.X` |

우리 프로젝트는 lazy import(함수 내부 import)를 쓰기 때문에 → **원본 모듈** `dev2.db.AsyncSessionLocal`을 패치해야 해요.

원칙: **"patch where it's looked up (찾는 곳을 패치해라)"**

## Q9. `ASGITransport(app=app)`이 뭐야?

**A.** FastAPI 앱을 실제 서버로 띄우지 않고도 테스트할 수 있게 해주는 도구예요.

- 실제 HTTP 소켓 연결 없음 → 빠름
- 테스트 코드 안에서 직접 앱을 호출

```python
transport = ASGITransport(app=app)  # 가짜 전송 레이어
async with AsyncClient(transport=transport, base_url="http://test") as client:
    r = await client.get("/insights/team")  # 실제 서버 없이 호출
```

httpx 버전 0.20 이후로 `AsyncClient(app=app)` 방식이 deprecated됐기 때문에 이 방식을 써야 해요.
