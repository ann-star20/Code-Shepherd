# 테스트 누락 가이드

> 짝 탐지기: **TEST-004 (테스트 누락)** · 분류: `테스트 누락` / 세부 `함수명`

## 우리 팀의 원칙
외부에서 호출되는 public 함수에는 단위 테스트가 하나 이상 있어야 합니다. "간단해서 테스트가 필요 없다"고 느껴지는 함수일수록, 나중에 조용히 동작이 바뀌어도 아무도 모르게 되는 위험이 큽니다. 테스트는 그 함수가 "지금 무엇을 하기로 약속했는지"를 코드로 박아두는 계약서입니다.

## 무엇을 먼저 테스트하나
모든 함수를 똑같이 다룰 필요는 없습니다. 비즈니스 규칙이 들어있는 함수, 돈·권한·외부 데이터를 다루는 함수, 버그가 났을 때 영향이 큰 함수부터 테스트합니다. 단순 위임(다른 함수 호출만 하는) 래퍼나 자명한 getter는 우선순위가 낮습니다.

## 테스트 작성·배치 규칙
테스트는 대상 모듈과 짝이 되는 위치(`tests/`)에 두고, "무엇을 검증하는지" 이름에서 드러나게 짓습니다. 한 테스트는 한 가지를 검증하고, 실패했을 때 원인이 바로 보이도록 작성하세요. 새 함수를 추가하는 PR이라면 그 함수의 테스트도 같은 PR에 포함하는 것이 우리 팀 기본값입니다.
