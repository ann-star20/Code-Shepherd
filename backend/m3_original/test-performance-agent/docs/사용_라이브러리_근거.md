# 📚 Dev3 사용 라이브러리 — 선정 근거 + 공식 문서

> 팀 요청: "어떤 라이브러리를 왜 썼고, 근거 문서는?"
> 원칙: **검증된 표준 도구는 가져다 쓰고, 도구가 못 하는 판별 로직만 직접 만든다.**

---

## 0. 한눈에 — 가져다 쓴 것 vs 직접 만든 것

| 구분 | 내용 |
|------|------|
| **라이브러리(조립)** | ast · pytest-cov · Docker · Pydantic · Gemini · Flask · requests · psycopg2 |
| **직접 구현(핵심)** | 탐지기 6종 판별 로직 · diff 교집합 필터 · 표준 출력 계약 · 게이트웨이 플러그인 구조 · 전체 파이프라인 |

→ "바퀴는 안 만들고, 그 위에 판단 로직을 얹었다."

---

## 1. 코드 분석 — `ast` (Python 표준 라이브러리)

| 항목 | 내용 |
|------|------|
| **용도** | 코드를 구조(나무)로 파싱 → 루프·함수·DB호출 위치를 정확히 추출 (N+1·복잡도 탐지의 기반) |
| **왜 이걸** | 정규식으로 코드 분석하면 부정확·취약. AST는 **언어 문법 기반**이라 정확. Python **내장**이라 추가 설치·의존성 0 |
| **대안 비교** | 정규식(부정확), `libcst`(무거움) → 표준 `ast`로 충분 |
| **공식 문서** | https://docs.python.org/3/library/ast.html |

---

## 2. 커버리지 측정 — `pytest` + `pytest-cov`

| 항목 | 내용 |
|------|------|
| **용도** | 테스트를 실제 실행해서 "어느 줄이 돌았나" 측정 → 라인/브랜치/함수 커버리지 |
| **왜 이걸** | Python 테스트의 **사실상 표준**. `--cov-report=json`으로 기계가 읽을 수 있는 결과 제공. 정적 추정이 아닌 **실측** |
| **대안 비교** | `coverage.py` 단독(가능하나 pytest 통합이 편함), `unittest`(기능 부족) |
| **공식 문서** | pytest: https://docs.pytest.org/ · pytest-cov: https://pytest-cov.readthedocs.io/ · coverage: https://coverage.readthedocs.io/ |

## 3. 격리 실행 — Docker

| 항목 | 내용 |
|------|------|
| **용도** | 신뢰 못 하는 신입 코드를 격리 컨테이너에서 실행 (안전 + 재현성) |
| **왜 이걸** | 남의 코드를 내 머신에 직접 실행하면 위험. Docker는 **격리·재현성·표준** 3박자. 팀 스택에 이미 존재 |
| **대안 비교** | venv(격리 약함), 직접 실행(위험), VM(무거움) → Docker가 표준 |
| **공식 문서** | https://docs.docker.com/ |

## 4. 데이터 검증 — Pydantic v2

| 항목 | 내용 |
|------|------|
| **용도** | 입출력 JSON 형식 강제·검증 (AgentOutput/Issue 계약). 잘못된 severity 등 자동 차단 |
| **왜 이걸** | FastAPI 등 현대 Python 표준. **타입 기반 자동 검증**으로 "계약 위반 데이터"를 코드 레벨에서 막음 → LLM 환각 출력 차단 |
| **대안 비교** | dataclass(검증 없음), 수동 검증(실수 많음) → Pydantic이 표준 |
| **공식 문서** | https://docs.pydantic.dev/ |

## 5. LLM — Google Gemini (`google-generativeai`)

| 항목 | 내용 |
|------|------|
| **용도** | 탐지된 이슈를 신입 수준에 맞춰 설명·예시코드·제안 생성 (코멘트 작성) |
| **왜 이걸** | 팀이 **Gemini 2.5 Flash로 통일** 결정. Flash는 **저비용·빠름**, 무료 티어 제공 → 데모·개발에 적합 |
| **대안 비교** | OpenAI GPT(유료), Claude(유료) → 비용·무료티어 이유로 Gemini 채택 |
| **공식 문서** | https://ai.google.dev/gemini-api/docs · 모델: https://ai.google.dev/gemini-api/docs/models |

## 6. Webhook 서버 — Flask

| 항목 | 내용 |
|------|------|
| **용도** | GitHub Webhook(PR 신호) 수신 서버 |
| **왜 이걸** | 가볍고 빠른 마이크로 웹 프레임워크. Webhook 엔드포인트 하나만 받으면 되는 단순 용도에 **과하지 않음** |
| **대안 비교** | FastAPI(비동기 강점이나 이 용도엔 과함), Django(무거움) → 단순 수신엔 Flask |
| **공식 문서** | https://flask.palletsprojects.com/ |

## 11. 직접 구현한 것 (라이브러리 아님)

> 아래는 라이브러리에 없는, **Dev3의 핵심 로직**. "왜 직접 만들었나" = 도구가 판단을 안 해주기 때문.

| 모듈 | 직접 만든 이유 |
|------|---------------|
| **탐지기 6종** (nplus1·complexity·coverage·missing_funcs·edge_cases·memory_leak) | "루프 안 DB호출=N+1" 같은 **판별 규칙**은 라이브러리에 없음. ast로 사실을 뽑고 판별은 직접 |
| **diff 교집합 필터** | "신입이 바꾼 함수 범위만 지적" 로직은 우리 요구사항 고유 |
| **표준 출력 계약** (AgentOutput) | Dev4·게이트웨이가 받아 쓸 형식 — 우리 시스템 전용 |
| **게이트웨이 플러그인 구조** | 여러 분석 에이전트를 등록·호출하는 오케스트레이션 — 직접 설계 |
| **AST=사실 / LLM=판단 분업** | 환각 방지를 위한 아키텍처 결정 — 우리 철학 |

## 12. 한 줄 답변 (팀에게)

> **"AST·pytest-cov·Docker·Pydantic·Gemini 같은 검증된 표준 라이브러리를 부품으로 쓰고, 그 위에 'N+1·복잡도 판별 로직 + 신입이 바꾼 부분만 추리기 + 표준 출력 계약'을 직접 구현했습니다. 바퀴는 재발명하지 않고, 도구가 못 하는 판단만 직접 만든 구조입니다."**
