
1. 동일 링크 요청 분기
runPipelineStart 가장 첫단계에서 문서 등록 프로세스 수행 전, 먼저 대상 링크의 ETag를 조회한다.
이후 document 테이블에서 original_url과 etag를 기준으로 동일한 문서가 존재하는지 확인한다.
- (original_url, etag) 조합이 동일한 데이터가 존재하는 경우 이미 지식화가 완료된 동일 버전의 문서로 판단하여 문서 등록 프로세스를 수행하지 않고 즉시 반환(return)하고, 사용자에게 "{링크주소}는 이미 지식화된 문서입니다." 팝업을 표시한다. 사용자가 "확인" 버튼을 클릭하면 해당 링크는 제외하고 다음 링크에 대한 작업을 계속 진행한다.
- (original_url, etag) 조합이 존재하지 않는 경우 신규 문서 또는 기존 문서의 변경된 버전으로 판단한다. 기존 문서 등록 프로세스를 정상적으로 수행한다.

2. HITL 단계 
링크들을 입력하고 파이프라인이 시작되면 runPipelineStart 에서 `/documents/${docId}/prescan` 결과가 없거나,  infer_confidence 값이 없거나 0.8보다 작은 링크들이 있다면 HITL 팝업을 띄워서 현재 결과값을(없으면 빈값으로) 링크별 framework, lang을 보여주되, 셀렉 박스로 사람이 등록되어있는 framework_metadata 테이블 값을 참고해서 직접 선택해 변경하거나, 입력하여 적용할 수 있게 만들어줘. 물론 작업 취소하기 버튼도 있어서 취소할 경우 documents 테이블의 doc_id 에 해당하는 데이터는 삭제되어야해.

3. 오류 링크 처리
크롤링 할 수 없는 링크가 들어올 경우, 유효한 주소가 아니거나 모종의 이유로 분석할 수 없는 경우,  pipeline_logs 테이블에 agent, level, message 값을 Crawler, ERROR, 구체적인 실패원인을 넣어주면돼. 또한  {/* URL 대기열 */} 영역 해당 링크의 가장 오른쪽에 "실패" 상태를 보여주고 mouse를 올리면 실패 메시지를 툴팁처럼 띄워줘.
